# Objections

An objection is strong when it names a mechanism by which the option fails and points at
evidence or at a gap that decides it. Weak objections are generic ("it is risky", "users may
not like it").

## Write one objection per option

- Steelman first: the best case for the option, then the strongest reason it fails.
- Tie it to a claim: a fact that contradicts the option, a gap the option depends on, or a
  hypothesis the option assumes.
- Name what would settle it: the data, test or source that makes it true or false.

## Judge each objection

- Verdict `accepted` (the option changes or falls) or `rejected` (with the reason and the claim
  that answers it). Never leave an objection without a verdict.
- An objection you cannot answer with a claim stays open and is shown to the user at Gate 2.

## Checks for the option set

- Are the options really different (different audience, mechanism or resource), or one idea
  reworded? Rewordings are merged.
- Is the best case for "keep as is" and for "close" stated honestly?
- Is any option missing that a competitor or the data obviously suggests?
